Umzug auf die neuen Konten

Die bisherige Installation erst nach erfolgreicher Prüfung der neuen abschalten. Der Wechsel überträgt weder Konten noch Daten automatisch.

1. Vorhandene Daten sichern

  1. In der bisherigen App als Spielleitung anmelden. Unter „Sicherung & Ausgabe“ eine Turniersicherung herunterladen. Sie enthält keine Mitgliedsanträge und keine Passwörter.
  2. Falls bereits private Anträge gespeichert wurden: „Mitgliedsanträge → Anträge öffnen → Alle als eine PDF herunterladen“. Datei prüfen und sicher aufbewahren.

2. Firebase im neuen Google-Konto

  1. Firebase Console öffnen und oben rechts das neue Google-Konto auswählen. Neues Projekt erstellen; der Spark-Tarif genügt innerhalb seiner Freikontingente. Analytics ist nicht erforderlich.
  2. „App hinzufügen“ → Websymbol </> → App registrieren. Firebase Hosting nicht erforderlich. Den gesamten Block firebaseConfig kopieren und zur Übernahme hier im Chat senden. Keine Passwörter oder privaten Dienstkontoschlüssel senden.
  3. Authentication → Anmeldemethode: E-Mail-Adresse/Passwort UND Anonym aktivieren. Die anonyme Anmeldung dient ausschließlich der geschützten Abgabe von Anträgen, sie erteilt keine Leserechte.
  4. Authentication → Nutzer → Nutzer hinzufügen. E-Mail und Passwort für die Spielleitung festlegen. Die UID dieses Nutzers kopieren.
  5. Firestore Database → Datenbank erstellen → Standard Edition, Datenbank-ID (default), passenden europäischen Speicherort wählen, Produktionsmodus verwenden.
  6. Firestore → Regeln: gesamten Inhalt der mitgelieferten firestore.rules einsetzen und veröffentlichen.
  7. Firestore → Daten: Sammlung roles anlegen. Dokument-ID = exakt die UID des gerade erstellten Nutzers. Vier Felder vom Typ String: role = admin, name = Vorstand, email = eure Anmelde-E-Mail, teamId = leer. Schreibweise beachten.
  8. Firestore → Indexe → Einzelnes Feld → Ausnahme hinzufügen: Sammlungs-ID membershipApplications, Feldpfad pdf; Indizierung deaktivieren. Die übrigen Ausnahmen stehen in firestore.indexes.json.

3. GitHub im neuen Konto

  1. Bei GitHub im neuen Konto anmelden. Neues öffentliches Repository anlegen, z. B. beerpong-turnier.
  2. Nach Eintrag der neuen Firebase-Konfiguration den Inhalt von ONLINE-PAKET hochladen, inklusive der Ordner DATEN, content, icons und vendor. index.html muss direkt im Repository liegen. Änderungen mit „Commit changes“ speichern.
  3. Repository → Settings → Pages → Deploy from a branch → main → /(root) → Save. Auf die Bereitstellung warten und den angezeigten Link öffnen.
  4. Firebase → Authentication → Einstellungen → Autorisierte Domains: NEUER-GITHUB-NAME.github.io hinzufügen, ohne https und ohne Repository-Pfad.

4. Prüfen und Daten übernehmen

  1. Neue Seite öffnen, als Spielleitung anmelden und Turnier anlegen. Bei Bedarf die gesicherte Turnierdatei wiederherstellen. Mitspieler-Konten im neuen Projekt neu anlegen und Teams zuordnen.
  2. Mit erfundenen Daten einen Antrag ausfüllen und beide Felder unterschreiben. Nach „geschützt abgeben“ muss eine Speicherbestätigung erscheinen. Unter Spielleitung den Antrag öffnen, Sammel-PDF herunterladen und beide Seiten prüfen. Anschließend Testantrag löschen.
  3. Auf einem zweiten Gerät ohne Admin-Anmeldung prüfen: keine Anträge sichtbar. Der Turnierplan muss weiterhin öffentlich funktionieren. Neue Adresse an die Teilnehmer verteilen; eine zuvor installierte App ggf. entfernen und von der neuen Adresse erneut installieren.

5. Alte Installation entfernen

Erst wenn alle benötigten Daten gesichert sind und das neue System geprüft ist:

  1. Im alten GitHub-Konto unter Repository → Settings → Pages die Veröffentlichung aufheben („Unpublish site“, falls angeboten, andernfalls Source deaktivieren). Das Repository kann als Archiv bestehen bleiben. Endgültig löschen nur, wenn du es wirklich nicht mehr benötigst.
  2. Im alten Firebase-Projekt unter Projekteinstellungen → Allgemein → Projekt löschen. Dabei unbedingt die alte Projekt-ID prüfen; alle dortigen Daten und Nutzer gehen verloren. Wenn andere Anwendungen das Projekt verwenden, das Projekt behalten und stattdessen nur diese Turnierdaten/Web-App entfernen.
  3. Falls früher FormSubmit aktiviert wurde, dessen Dienst wird von dieser neuen App nicht mehr angesprochen. Bereits im Postfach liegende alte E-Mails und Anhänge werden durch den Kontowechsel nicht automatisch gelöscht.

So funktioniert der private Eingang

Die App erstellt das PDF auf dem Gerät und speichert es als Binärdatei in der geschützten Sammlung membershipApplications. Keine E-Mail und kein externer Versanddienst. Nur eine gespeicherte Admin-Rolle darf die PDFs lesen oder löschen. Gäste dürfen mit temporärer Anmeldung neue Anträge abgeben, aber keine Anträge abrufen oder verändern. Pro PDF sind maximal 900 KB zugelassen; private PDFs werden nicht vom Service Worker gespeichert. Nach Bearbeitung die Anträge löschen. Eine hohe Zahl unerwünschter Abgaben kann Freikontingente ausschöpfen; bei öffentlicher Verbreitung kann zusätzlich Firebase App Check eingerichtet werden.

Technische Grundlagen: anonyme Anmeldung und Firestore-Grenzen und Freikontingente.
