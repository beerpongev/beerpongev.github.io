BEERPONG ACADEMY · VERÖFFENTLICHUNG

Von deinem GitHub-Konto zur fertigen Turnier-App.

Du brauchst ein GitHub-Konto, ein Google-Konto für Firebase und Zugriff auf beerpongacademy@gmail.com, um den Versand der Mitgliedsanträge freizuschalten. Die Einrichtung erfolgt im Browser. Du brauchst dafür weder Git noch Node.js zu installieren.

Aktueller Stand: Die Dateien sind vorbereitet; die App ist noch nicht auf deinem GitHub-Konto veröffentlicht. In config.js stehen zunächst Platzhalter. Ohne deine Firebase-Werte zeigt die App eine lokale Demo.

1. Dateien vorbereiten

  1. Den Ordner TURNIER öffnen. Darin liegen der vollständige Quellcode und die vorbereitete Auswahl für die Veröffentlichung im Unterordner ONLINE-PAKET. Lade später dessen Inhalt hoch, nicht den gesamten übergeordneten Programmierordner.
  2. Optional zuerst lokal ausprobieren. Öffne STARTEN.cmd im Ordner TURNIER und danach http://127.0.0.1:5173 im Browser. Das Startskript kann eine vorhandene VS-Code-Laufzeit nutzen; alternativ funktioniert installiertes Node.js. In der Demo kannst du oben Zuschauer, Mitspieler und Spielleitung wählen. Das sind lokale Beispieldaten, keine echten Konten. Zum Beenden das Konsolenfenster schließen.
  3. Dateiendungen sichtbar machen. Im Windows-Explorer unter Ansicht → Anzeigen → Dateinamenerweiterungen einschalten. Das hilft beim Bearbeiten von config.js: Die Datei darf nicht versehentlich config.js.txt heißen.

2. Dein kostenloses Firebase-Projekt einrichten

GitHub liefert die Webseite aus. Firebase übernimmt Anmeldung, Rechte und Live-Daten. Der kostenlose Spark-Tarif benötigt grundsätzlich kein Zahlungsmittel; seine Nutzung hat Grenzen. Aktiviere für diese Anleitung keine kostenpflichtige Abrechnung. Offizielle Tarifübersicht.

  1. Firebase Console öffnen. Mit deinem Google-Konto anmelden. Falls du noch keines hast, zunächst ein Google-Konto anlegen. Das Firebase-Konto muss nicht dieselbe Adresse wie das GitHub-Konto verwenden.
  2. Ein neues Projekt erstellen. Wähle einen Namen wie Beerpong Academy Turnier und folge dem Assistenten. Google Analytics wird für diese App nicht benötigt. Falls eine Tarifauswahl erscheint, bei Spark / kostenlos bleiben. Ein eigenes Firebase-Projekt und eine Web-App sind Voraussetzung für die Konfiguration. Firebase-Web-Einrichtung.
  3. Eine Web-App registrieren. Auf der Projektübersicht das Web-Symbol </> wählen. Einen App-Namen vergeben. Firebase Hosting muss nicht mit eingerichtet werden, weil du GitHub Pages verwendest. Anschließend werden Konfigurationswerte angezeigt.
  4. Die Werte in config.js einsetzen.

    Im Explorer Rechtsklick auf TURNIER/config.js → Öffnen mit → Editor. Die Werte innerhalb der Anführungszeichen ersetzen:

    export const firebaseConfig = {
  apiKey: "DEIN_WERT_AUS_FIREBASE",
  authDomain: "DEIN-PROJEKT.firebaseapp.com",
  projectId: "DEIN-PROJEKT",
  storageBucket: "DEIN_WERT_AUS_FIREBASE",
  messagingSenderId: "DEIN_WERT_AUS_FIREBASE",
  appId: "DEIN_WERT_AUS_FIREBASE"
};

    Die vorhandenen Namen, Kommata und Klammern beibehalten. tournamentId bleibt main, useEmulators bleibt false. Mit Strg+S speichern. Bei Bedarf findest du die Werte wieder über das Zahnrad → Projekteinstellungen → Allgemein → Deine Apps.

    Wichtig für das vorbereitete Upload-Paket: Kopiere die gerade gespeicherte config.js anschließend auch nach TURNIER/ONLINE-PAKET/config.js und ersetze dort die Platzhalterdatei.

    Die Firebase-Web-Konfiguration ist absichtlich öffentlich. Schutz entsteht durch Anmeldung und Datenbankregeln. Niemals Gmail-Passwörter, Service-Account-Dateien oder Admin-SDK-Schlüssel eintragen. Offizielle Erklärung zu Firebase-API-Schlüsseln.

  5. E-Mail-/Passwort-Anmeldung einschalten. In Firebase Authentication öffnen; je nach Console-Version liegt der Punkt unter Security oder Build. Auf Get started / Jetzt starten klicken. Unter Sign-in method / Anmeldemethode den Anbieter E-Mail/Passwort aktivieren und speichern. Die zusätzliche Anmeldung per E-Mail-Link ist nicht erforderlich. Anbieter einrichten.
  6. Firestore-Datenbank erstellen. Firestore Database öffnen, gegebenenfalls unter Databases & Storage oder Build. Datenbank erstellen wählen. Nutze Standard Edition und die Datenbank-ID (default). Eine EU-Region wie Frankfurt wählen, sofern verfügbar. Als anfänglichen Regelmodus Produktionsmodus wählen. So bleibt der Zugriff zunächst geschlossen. Firestore-Einrichtung.
  7. Die mitgelieferten Sicherheitsregeln veröffentlichen. Lokal TURNIER/firestore.rules im Editor öffnen → Strg+A → Strg+C. In Firebase bei Firestore den Reiter Regeln / Rules öffnen, den vorhandenen Inhalt vollständig ersetzen und auf Veröffentlichen / Publish klicken. Eine erfolgreiche Veröffentlichung abwarten. Das Hochladen der Datei zu GitHub allein aktiviert diese Regeln nicht.

3. Dein erstes Spielleitungskonto anlegen

Diese einmalige Einrichtung machst du als Besitzer des Firebase-Projekts. Spätere Konten kannst du direkt im Admin-Bereich der App verwalten. Ein neues Authentication-Konto allein hat noch keine Schreibrechte.

  1. In Firebase zu Authentication → Nutzer wechseln. Nutzer hinzufügen / Add user wählen. Deine gewünschte Anmelde-E-Mail und ein starkes Passwort eintragen und speichern. Kopiere danach die UID dieses Kontos. Die UID ist eine technische Kennung; sie ist weder die E-Mail-Adresse noch das Passwort.
  2. Das Rollendokument anlegen. In Firestore zum Reiter Daten / Data gehen. Sammlung starten / Start collection wählen und als Sammlungs-ID exakt roles eintragen. Als Dokument-ID exakt die kopierte UID verwenden, nicht „Auto-ID“.
  3. Vier Felder als Typ „String“ hinzufügen. Schreibweise und Groß-/Kleinschreibung genau übernehmen:
    FeldnameTypWert
    roleStringboard
    nameStringDein Anzeigename
    emailStringE-Mail des eben angelegten Kontos
    teamIdStringLeer lassen. Das Feld anlegen, als Wert aber keine Zeichen eingeben.

    Speichern. Für den ersten Vorstand muss der Wert technisch board heißen. Weitere Spielleitungskonten erhalten admin, Mitspieler player. Nur Vorstandsmitglieder dürfen auf die Anträge zugreifen. Das leere Feld teamId ist erforderlich; weder weglassen noch null, ein Leerzeichen oder die Buchstaben "" als Wert eingeben.

4. Die Webseite auf GitHub Pages veröffentlichen

Mit GitHub Free verwendest du dafür ein öffentliches Repository. Es enthält den App-Code und die freigegebenen Dokumente, keine Passwörter und keine gespeicherten Mitgliedsanträge. GitHub-Pages-Voraussetzungen.

  1. Bei GitHub anmelden. Oben rechts auf + → New repository klicken. Einen Repository-Namen wie beerpong-turnier eintragen, Public auswählen und Create repository wählen. Ein README kannst du mit anlegen lassen.
  2. Die vorbereiteten App-Dateien hochladen. Im neuen Repository auf Add file → Upload files klicken. Bei einem ganz leeren Repository steht stattdessen häufig uploading an existing file. Im Explorer TURNIER/ONLINE-PAKET öffnen und dessen Inhalt in den Upload-Bereich ziehen. Die Unterordner DATEN und content müssen mitkommen; nicht den Ordner ONLINE-PAKET selbst als oberste Ebene hochladen.
  3. Vor dem Speichern die Struktur prüfen. Unter anderem müssen folgende Pfade entstehen: 
    index.html

    Die tatsächlich vorbereiteten Dateien vollständig übernehmen, auch weitere Module im Paket. index.html muss direkt auf der obersten Ebene stehen. Gib als Beschreibung z. B. „Turnier-App veröffentlichen“ ein und speichere den Upload über Commit changes; falls GitHub einen neuen Branch/Pull Request vorschlägt, die Änderungen anschließend nach main übernehmen. Bei Browser-Uploads gelten maximal 100 Dateien pro Vorgang und 25 MiB je Datei; das Paket ist für diesen Weg vorbereitet. Dateien über den Browser hochladen.

  4. Pages einschalten. Im Repository Settings → Pages öffnen. Im Bereich Build and deployment für Source die Einstellung Deploy from a branch wählen. Als Branch main, als Ordner /(root) auswählen und Save klicken. Offizielle Veröffentlichungseinstellungen.
  5. Die Veröffentlichung abwarten. Die Pages-Seite nach einigen Minuten erneut aufrufen. Die dort angezeigte Webadresse öffnen. Für das Beispiel lautet sie ungefähr https://DEIN-GITHUB-NAME.github.io/beerpong-turnier/. Verwende die tatsächlich von GitHub angezeigte Adresse. Unter Actions kannst du den Veröffentlichungsstatus und Fehler sehen.
  6. Die App-Domain bei Firebase ergänzen. In Firebase Authentication → Settings → Authorized domains / Autorisierte Domains öffnen. DEIN-GITHUB-NAME.github.io hinzufügen, ohne https:// und ohne /beerpong-turnier/. Für lokale Auth-Tests gegebenenfalls auch localhost und 127.0.0.1 ergänzen; neuere Firebase-Projekte enthalten localhost nicht automatisch. Hinweis zu autorisierten Domains.

5. Das echte Turnier einrichten

  1. Die veröffentlichte App öffnen und anmelden. Anmelden wählen und die E-Mail sowie das Passwort aus Schritt 11 eingeben. Der Reiter Spielleitung muss erscheinen. Falls noch kein Turnier existiert, Turnier anlegen wählen. Ein gelber Demo-Rollenschalter darf bei eingetragener Live-Konfiguration nicht mehr erscheinen.
  2. Teams zuerst anlegen. Unter Teams oder Spielleitung → Teams verwalten die Teamnamen und jeweils beide Personen erfassen. Teams können zunächst ohne Gruppe bleiben. 32 Teamplätze anlegen bereitet bei einem leeren Turnier die Plätze vor; die Personennamen anschließend ergänzen.
  3. Danach Gruppen zuweisen. Unter Teams → 2. Gruppen zuweisen die Teams auf A bis H verteilen. Jede Gruppe benötigt vier Teams. Für einen Tausch zunächst ein Team auf Ohne Gruppe setzen. Alternativ kann die Spielleitung die Gruppen auslosen.
  4. Mitspieler-Konten anlegen und zuordnen. Unter Spielleitung → Benutzer & Teamzuordnung → Konto anlegen Anzeigename und E-Mail eintragen. Als Rolle Mitspieler wählen und das richtige Team auswählen. Mehrere Personen können dasselbe Team haben. Beim Anlegen wird eine Firebase-E-Mail zum Festlegen eines eigenen Passworts angefordert. Den Link vor der ersten Anmeldung öffnen. Ein Startpasswort wird nicht versendet. Technische Rollenwerte sind board (Vorstand), admin (Spielleitung), player und guest.
  5. Tische und Eingaberechte festlegen. Unter Spielleitung → Tische jetzt einstellen die verfügbare Anzahl eintragen. Der zentrale Schalter Mitspieler dürfen Ergebnisse ihrer eigenen Spiele eintragen und korrigieren erlaubt oder sperrt die Selbsteingabe für alle Teams. Fremde Spiele bleiben für Mitspieler gesperrt. Bei gesperrter Selbsteingabe melden sie das Ergebnis der Spielleitung.
  6. Die Gruppenphase starten. Erst bei 32 vollständigen Teams und acht gefüllten Gruppen Gruppenphase starten wählen. Die Tischvergabe läuft fortlaufend. Manuelle Zuweisungen bleiben möglich. Für die Übergänge in die KO-Phasen gibt es konkrete Knöpfe wie Achtelfinale starten. Nach Verlängerung werden unabhängig von den tatsächlichen Restbechern Sieger 0 und Verlierer 1 Restbecher gewertet; die Tabellen-Differenz beträgt +1 für den Sieger und −1 für den Verlierer; die Becherauswahl ist dann deaktiviert.

6. Geschützte Mitgliedsanträge

Bei einem bestehenden Projekt bitte zuerst die Update-Anleitung für Vorstandsrechte und Tischablauf beachten.

Keine E-Mail-Einrichtung erforderlich. Zusätzlich zur E-Mail/Passwort-Anmeldung in Firebase Authentication die Methode Anonym aktivieren. Aktuelle firestore.rules veröffentlichen. Unter Firestore → Indexe → Einzelnes Feld eine Ausnahme für Sammlung membershipApplications, Feld pdf ohne Indizierung hinzufügen.

Mitgliedschaft ausfüllen, beide Felder unterschreiben und der geschützten Speicherung zustimmen. Nach der Speicherbestätigung liegt das PDF unter Vorstand → Mitgliedsanträge → Anträge öffnen bereit. Dort lassen sich alle Anträge als zusammenhängende PDF herunterladen und einzeln löschen. Nur der Vorstand hat Zugriff. Mit einem erfundenen Testantrag prüfen, bevor echte Anträge eingehen.

Wechsel auf ein anderes GitHub-/Firebase-Konto: vollständige Umzugsanleitung. Die bestehenden Vereinsangaben und Erklärungen vor Freischaltung auf Aktualität prüfen.

7. Vor dem Turnier auf zwei Geräten prüfen

  1. Den öffentlichen Link auf einem zweiten Gerät ohne Login öffnen: Spielplan, Gruppen, Regelwerk und Mitgliedschaft müssen lesbar sein; Ergebnisse dürfen nicht veränderbar sein.
  2. Als Mitspieler anmelden: Das richtige Team wird als Dein Team hervorgehoben. Bei erlaubter Selbsteingabe lässt sich nur ein eigenes Spiel bearbeiten.
  3. Den zentralen Eingabeschalter sperren: Mitspieler können anschließend kein Ergebnis ändern. Die Spielleitung kann weiterhin eintragen.
  4. Ein Testergebnis eingeben: Das zweite Gerät muss sich ohne Neuladen aktualisieren. Verlängerung, automatische Tischvergabe und eine vorgemerkte manuelle Tischzuweisung ausprobieren.
  5. Vor dem Leeren der Testdaten eine Sicherung herunterladen. Turnier zurücksetzen verlangt zwei Bestätigungen; ein Abbruch darf keine Daten ändern. Das Zurücksetzen erhält Teams, Gruppen und Benutzer.
  6. Optional auf Smartphones über das Browser-Menü App installieren / Zum Startbildschirm hinzufügen wählen. Auf iPhone/iPad in Safari über Teilen → Zum Home-Bildschirm. Danach den Link bzw. die installierte App an die Teilnehmer weitergeben.
Bereit für den Abend: Die veröffentlichte URL ist erreichbar, Firebase zeigt Live-Verbindung, das Spielleitungskonto funktioniert, Mitspieler sind den richtigen Teams zugeordnet und der E-Mail-Eingang wurde tatsächlich geprüft.
